## 3. 5-10 分钟演示顺序

1. 登录系统，说明这是面向 Web 项目的自动化测试平台。
2. 进入“项目/环境”，说明项目级资产管理与环境变量隔离。
3. 进入“用例”，打开一条 `[论文]` 或 SauceDemo 用例，展示 HTTP / UI 步骤、变量、断言、截图与报告能力。
4. 点击“立即执行”或“自适应执行”，说明任务状态、执行日志、步骤结果和失败证据留存。
5. 进入“套件”，运行一个预置套件，说明多用例顺序编排和套件级历史记录。
6. 进入“性能”，展示 Locust 脚本导出、压测记录和响应时间图表。
7. 打开“质量评分 / Flaky 分析”，说明 Wilson 上界、状态切换率、EWMA 如何形成风险分和建议重试。

## 5. 高频追问回答要点

- 为什么不是普通 CRUD 系统：核心价值在执行闭环，能管理用例、真实运行、记录日志、生成报告、分析 Flaky 风险。
- 自适应策略证明了什么：本批实验证明“分析—决策—执行—回流”闭环可复现；由于观测成功率均为 1.000，不外推为显著提升。
- 为什么用 Wilson / EWMA：Wilson 用于小样本下保守估计失败率上界，EWMA 强化近期失败趋势，切换率描述成败抖动。
- 为什么前端测试不多：当前前端单测覆盖认证链路和公共组件，复杂页面交互以演示和后续端到端测试完善。
- 项目不足：前端复杂交互测试仍可补充，执行引擎和部分页面文件偏大，生产部署应使用 PostgreSQL + Redis + 独立 Worker。
